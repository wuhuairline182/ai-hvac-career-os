# 安全边界

## 永远不要提交

- ERP 账号和密码
- session/token
- 验证码图片
- 登录态 JSON
- 客户合同、采购明细、报销单、供应商联系人
- ERP 原始导出
- 带真实金额的大批量经营数据

## 推荐做法

- 用 `.env` 存本地账号密码。
- `.env.example` 只放字段名，不放真实值。
- GitHub 仓库优先设为 private。
- 文档里写接口路径和方法，不写真实登录态。
- 样例数据全部脱敏。
- 写入脚本默认 dry-run，只有显式参数才执行。

## 公司边界

如果 ERP 里有多家公司，脚本默认应该只处理目标公司分类前缀，例如：

```text
目标公司->
```

不要跨公司修改产品、分类、采购、客户数据。
